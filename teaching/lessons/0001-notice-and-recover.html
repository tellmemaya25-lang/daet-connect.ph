Notice the dumb zone, then pick one move

The idea

Everything in a session (your messages, file reads, tool output, failed attempts) competes for the model's attention. Anthropic calls this an attention budget: as the context grows, "the model's ability to accurately recall information from that context decreases" (Anthropic Engineering). Chroma measured this across 18 models and found reliability falls as input grows even on simple tasks, and worst when irrelevant text looks similar to what you want (Context Rot).

Two honest caveats. The decline is gradual, not a cliff, so there is no single magic percentage; community numbers (40–70%) disagree. And Anthropic's current docs say running out of context is "rare" with 1M-token windows, but /clear between tasks is "still worth doing, because a focused context gets you better answers" (Best practices). The enemy is clutter, not just size.

Your win: three signals, three moves

SignalMove
Same mistake corrected twice, still wrong/clear, then one new prompt that folds in what you learned
Finished a task, starting an unrelated one/clear (costs nothing)
Went down a bad path, but earlier work was good/rewind (or Esc twice) to before the detour
Same task, history is long and stale/compact with a focus, e.g. "keep the API changes and test commands"
Noisy search or independent review neededDelegate to a subagent; it returns a short summary

All five from Best practices for Claude Code; subagent summaries per Anthropic.

Make it survive a reset

Anything that must outlive /clear belongs in a file: this repo's AGENTS.md and CONTEXT.md, or a scratch NOTES.md (Anthropic's "structured note-taking"). Keep those files short; Anthropic's docs say if a line is getting lost in a long file, "the file needs to be shorter."

Retrieval practice

Answer from memory before peeking at the table.
