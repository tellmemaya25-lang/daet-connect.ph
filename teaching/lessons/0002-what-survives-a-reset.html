See your context, and know what survives /compact

The idea

Lesson 1 gave you the moves. This one stops you guessing. Claude Code's window holds "your instructions, the files it reads, its own responses, and content that never appears in your terminal" (Explore the context window). Some of it is loaded before you type: CLAUDE.md (AGENTS.md can load in its place), auto memory, MCP tool names and skill descriptions. Every file read adds more.

To see the real numbers, run /context: "a live breakdown by category with optimization suggestions." Run /memory to open the files it lists.

Your win: where should this go?

After /compact the conversation becomes a summary. What comes back unchanged is only what lives on disk:

Survives intactGets summarized away
Project-root CLAUDE.md and unscoped rules (re-injected from disk)Rules you typed in chat
Auto memoryRules with paths: frontmatter and nested CLAUDE.md, once loaded
Plan-mode planContext that hooks added earlier
Up to five most recent files, re-read (a file over 5,000 tokens returns as a path only)Everything else you read

From the "What survives compaction" table in Explore the context window. Path-scoped rules reload on demand when their trigger file is touched again.

Rule of thumb. If losing it would hurt, it must live in a file, not in chat. If it is a hard rule, keep it in the project-root instruction file. Before a long new task, /compact focus on the auth bug fix keeps what you choose rather than "what the automatic pass guesses is important."
